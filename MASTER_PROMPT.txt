====================================================
GLOBAL STRICT RULES FOR BOTH AGENTS
====================================================

1. SOURCE OF TRUTH
The complete Project Labs Master Build Specification v2.0 appended below is
authoritative.

2. NO REQUIREMENT LOSS
Every module, feature, field, workflow, status, role, API area, database
domain, security requirement, UI requirement, phase, future capability, and
architectural rule in the specification must remain traceable.

3. DO NOT GUESS
If something is unclear:
- identify the exact source requirement
- identify the dependency
- identify the affected agent
- identify the blocker
- preserve the requirement
Never silently invent behavior.

4. DO NOT DELETE FEATURES
A feature that belongs to a later phase must remain architecturally possible.
Do not remove it just because it is not being implemented now.

5. PHASE CONTROL
Implement according to Phase 1 → Phase 2 → Phase 3 → Phase 4.
Do not randomly jump between modules unless a dependency requires it.

6. PRODUCTION QUALITY
Do not create throwaway architecture that will need to be replaced later.
Prefer modular, typed, secure, maintainable implementation.

7. NO FAKE COMPLETION
Never claim a feature is complete if its required API, database, UI,
validation, authorization, error handling, or integration is missing.

8. NO FAKE DATA IN PRODUCTION FLOWS
Mocks may be used temporarily for isolated UI development only and must be
clearly marked and replaceable. Never treat mocks as real backend behavior.

9. NO SECURITY BY UI
Hiding a button is NOT authorization.
Backend permissions are authoritative.

10. NO DIRECT FRONTEND DATABASE ACCESS
Frontend communicates with backend APIs only.

11. NO SECRETS IN FRONTEND
Never expose:
- database credentials
- JWT secrets
- refresh secrets
- SMTP credentials
- Evolution API key
- storage credentials
- private backend configuration

12. NO BUSINESS LOGIC DUPLICATION
Authoritative calculations and business rules belong to backend.
Frontend may perform UX-level validation only.

13. PUBLIC/PRIVATE DATA SEPARATION
Public API responses must never expose internal financial, supplier, client,
or operational information.

14. API CONTRACT DISCIPLINE
Never silently rename endpoints, fields, enums, IDs, query parameters,
pagination formats, error formats, or response structures.

15. SHARED CONTRACT
Both agents must agree on:
- endpoint
- HTTP method
- request schema
- response schema
- error schema
- authentication
- authorization
- IDs
- enums
- pagination
- filters
- sorting
- timestamps
- file references
- feature flags

16. SHARED FILE CONFLICT PREVENTION
When both agents work in one repository:
- avoid editing the same files unnecessarily
- keep modules isolated
- create feature-specific files
- avoid giant shared files
- do not overwrite another agent's work

17. TRACEABILITY
Every implementation must be traceable back to the master specification.

18. CHANGE CONTROL
If an API or architecture change is necessary, record:
- reason
- affected module
- endpoint
- method
- request change
- response change
- frontend impact
- backend impact
- migration impact if any

19. DO NOT BUILD UNREQUESTED GIANT SYSTEMS
Do not transform Project Labs into:
Jira, Salesforce, HubSpot, WordPress, QuickBooks, Slack, Shopify,
full accounting software, full HRMS, full payment gateway platform,
or a complex AI chatbot platform.

20. V1 FOCUS
Keep the product:
Simple enough to operate.
Powerful enough to scale.
Flexible enough to evolve.

infrastructure of a new innovation company.

The public website communicates the
identity.

The CRM manages customers.

The sales system manages opportunities.

The quotation system manages commercial
proposals.

The project system manages delivery.

The R&D system manages research.

The experiment system manages
experimentation.

The inventory system manages physical
resources.

The product system manages future products.

The finance system tracks business
performance.

The support system manages post-delivery
relationships.

The CMS manages public content.

The automation engine connects business
events.

The analytics layer tells management what
is happening.

Together, these systems form the Project
Labs Company Operating Platform.
